## 交接目標與範圍

目標是讓新人能在沒有你協助的情況下，自己輸出 APK，並調整地圖、事件、角色與卡牌數值。交接範圍要等「現在的遊戲距離最終版還差什麼」確定後才能定案。

**交接完成的標準（來自筆記）**

- [ ] 能自己輸出可安裝的 APK
- [ ] 能調整現有資料：地圖、事件、角色數值、卡牌

**建議補充的標準**

- [ ] 能從 Google Sheet 讀取表單並通過驗證（數值類資料都經過這步）
- [ ] 能用開發者測試器重現並測試單場戰鬥
- [ ] 能到 Sentry 查線上錯誤，或請玩家匯出 Log

**範圍取決於「距離最終版還差什麼」**

| 如果主要缺的是… | 新人需要的能力 | 需不需要寫程式 |
| --- | --- | --- |
| 數值平衡 | Google Sheet 改數值、讀表單、測試 | 不需要 |
| 更多卡牌 | 上述能力 + 建立 CardData、加入牌組；若要新效果就要寫 Effect | 視效果而定 |
| 更多角色 | 建立 AllyData、初始牌組、專屬遺物（遺物要寫程式）、美術資源 | 需要 |
| 更多關卡與地圖 | 編輯 Stage、節點、敵人組合、事件 | 多半不需要 |

**待討論**

1. 上表四項中，哪一項是接下來最主要的工作？這會決定新人要不要會寫 C#。（暫定：數值平衡）
2. 新人是「維運」（調數值、修 bug、發版）還是「繼續開發」？兩者的交接深度差很多。
3. 交接後你是否還能提供諮詢？建議約定一段支援期（例如 1 個月）與聯絡管道。
4. 交接對象有幾位？若多人，是否要分工（例如一位負責程式與發版，一位負責企劃與數值）？

## 時程

交接依過關條件推進，不依日期；等你確定開始日與每週可投入的時間，再幫各階段排上日期。

| 階段 | 內容 | 過關條件 |
| --- | --- | --- |
| 0 | 確認範圍與人選 | 交接範圍與完成標準寫下來，雙方同意 |
| 1 | 新人事前準備 | 事前準備清單全部勾選，帶著問題清單進入交接 |
| 2 | 知識移轉（帶著做，4 場） | 4 場完成 |
| 3 | 實作驗收 | 新人獨立完成全部任務 |
| 4 | 權限轉移與收尾 | 新人用自己的帳號完成一次完整流程 |

階段 1 與階段 0 的「確認新人程度」可以部分並行，其餘階段要依序進行。

## 各階段內容

交接分五個階段，每個階段結束都有一個「過關條件」，沒過就不進下一段。

### 階段 0：確認範圍與人選（你與專案負責人）

- 整理「目前版本與最終版的差距」，排出優先順序（見「交接目標與範圍」）。
- 跟新人確認：人數、Unity 經驗、常用的 AI 開發工具、使用 Mac 或 Windows。
- **過關條件**：交接範圍與完成標準有寫下來，雙方同意。

**方案：新人的 Unity 程度不足時**

| 方案 | 做法 | 優點 | 缺點 |
| --- | --- | --- | --- |
| A. 先自學再交接 | 指定 Unity Learn 的基礎課程，完成後再開始 | 你花的時間最少 | 拉長整體時程 |
| B. 只教「這個專案用得到的」 | 只教 Inspector、Prefab、ScriptableObject、場景、Build | 最快上手 | 遇到範圍外的問題會卡住 |
| C. 只做企劃型交接 | 新人只改 Google Sheet，由別人負責讀表與發版 | 幾乎不用會 Unity | 還是需要另一位會 Unity 的人 |

### 階段 1：新人事前準備（自行完成）

- [ ] 具備基礎 Unity 操作知識
- [ ] 安裝 Unity 2021.3.30f1，**包含 Android Build Support 模組**（輸出 APK 必需）
- [ ] Clone 專案並能正常開啟、從主選單按 Play
- [ ] 有自己的 AI 開發工具（Claude、OpenCode、Kilo 等）
- [ ] 至少玩過並通關一次遊戲
- [ ] 讀過 `Docs/Handover.md`，並用 AI 工具請它介紹專案，寫下 3 個看不懂的地方

**過關條件**：以上全部勾選，帶著問題清單進入面對面交接。

**提案**

- 在 repo 根目錄加一份 `CLAUDE.md` 與 `AGENTS.md`（內容可指向 Handover.md），不論新人用 Claude、OpenCode 或 Kilo，AI 一開始就能讀到專案背景。
- 「通關一次」可能耗時較久，可允許用作弊面板加速，重點是走完整個流程。

### 階段 2：知識移轉（帶著做）

建議分 4 次進行，每次讓新人操作、你在旁邊看：

| 場次 | 主題 | 內容 |
| --- | --- | --- |
| 1 | 專案導覽 | 資料夾結構、GameManager 與各子系統、場景流程 |
| 2 | 資料維運 | Google Sheet → 讀取表單 → 驗證；地圖、事件、角色、卡牌各改一次 |
| 3 | 建置與發版 | 輸出 APK、版本號、安裝到手機測試 |
| 4 | 除錯與工具 | 開發者測試器、作弊面板、Log、Sentry |

**提案**

- 每場錄影，後續新人（或再下一任）可以重看。
- 文件目前分散在 HackMD、Milanote、Google Sheet 與 repo 內。建議以 `Docs/Handover.md` 為唯一入口，其他文件只放連結，避免新人不知道該信哪一份。

### 階段 3：實作驗收（新人獨立完成）

由新人自己完成以下任務，你只看結果，不幫忙操作：

- [ ] 改一張卡的費用與傷害，讀取表單，在遊戲中看到變化
- [ ] 新增一張卡片並加入某個職業的獎勵牌組
- [ ] 調整一個角色的血量與初始牌組
- [ ] 新增一個地圖事件（含至少兩個選項）
- [ ] 調整一個關卡的地圖節點或敵人組合
- [ ] 輸出 APK，安裝到手機並玩到第一場戰鬥
- [ ] 以上變更都用 Git commit，且訊息清楚

**過關條件**：全部任務完成，且過程中沒有需要你介入。練習用的變更建議做在獨立分支，驗收後再決定要不要合進 main。

### 階段 4：權限轉移與收尾

| 項目 | 要做的事 |
| --- | --- |
| GitHub Repo | 加新人為 collaborator；考慮是否要轉到組織帳號 |
| Google Sheet 配置表 | 給編輯權；考慮轉移擁有權 |
| eMath 題庫 API | 介紹新人給題庫端窗口，確認 Token 是否要更換 |
| Sentry | 加入專案成員 |
| 付費套件 | 確認 Odin、Easy Save 3、Feel、Cartoon FX 的授權是否包含新人 |
| Android 簽章金鑰（Keystore） | 目前專案沒有設定，見下方待討論 |
| 上架帳號 | 若有 Google Play 開發者帳號，要加入新人 |

**過關條件**：新人用自己的帳號完成一次「改資料 → 讀表 → commit → 輸出 APK」，全程不用你的帳號。

**待討論：APK 要怎麼發佈？**

專案目前沒有自訂 Keystore，輸出的 APK 用的是每台電腦各自的 debug 簽章，Android 的 Application Identifier 也未設定。

| 方案 | 適用情境 | 需要做的事 |
| --- | --- | --- |
| A. 維持 debug 簽章 | 只在校內或活動中直接安裝 APK | 不同人輸出的版本無法直接覆蓋安裝，要先移除舊版 |
| B. 建立正式 Keystore | 有對外發布或要上 Google Play | 建立 Keystore、設定 Package Name、以密碼管理工具保存；遺失後無法再更新同一個 App |

## 風險與待決事項

最大的風險是「只有你知道」的東西：帳號、金鑰與沒寫下來的經驗，這些應該在你離開前全部轉移或文件化。

| 風險 | 影響 | 建議做法 |
| --- | --- | --- |
| 帳號與資料在你個人名下（GitHub、Google Sheet、Sentry） | 你離開後新人無法管理權限 | 轉到單位共用帳號或組織，或至少再加一位管理者 |
| 題庫 API Token 寫死在程式且在 Git 歷史 | 有 repo 存取權的人都能使用 | 交接前跟題庫端確認是否更換 |
| 文件分散且可能過時（HackMD、Milanote） | 新人照舊文件操作出錯 | 以 Docs/Handover.md 為主，檢查舊文件後標註「已過時」或整併 |
| 沒有自動化測試 | 新人改程式容易弄壞戰鬥 | 整理一份「發版前手動測試清單」 |
| 付費套件授權不明 | 新人使用可能違反授權 | 確認購買者與授權條款 |
| Android 發布設定未完成（無 Keystore、無 Package Name） | 版本無法覆蓋安裝、無法上架 | 在階段 4 定案發布方式 |

5. 交接後的支援期要多長？問題透過什麼管道問你？
